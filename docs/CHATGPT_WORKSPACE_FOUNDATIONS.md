# SSR-viet-truyen — ChatGPT Workspace Foundations (2026-10-11)

Branch: `feat/chatgpt-workspace-foundations-20261011`

## Scope
This change begins four independently verifiable capabilities. It is **not** a
claim that the whole autonomous ChatGPT publishing pipeline or Batch Writer UI
is finished. The office computer is excluded; private test-1 content is not
committed to GitHub.

### 1. ChatGPT-deferred postprocessing
- For a Vietnamese project, manual **Finalize** carries
  `chatgptDeferred: true`.
- The native finalization transaction and manuscript publication remain
  unchanged; the original code still links the authoritative finalization.
- The `kb_import` step still uses the existing app repository/projection.
- `chapter_notes` and `character_cards` are **not generated by local AI**.
  `RunFinalizePostProcessCommand.executeKnowledgeOnly` bypasses the provider
  runtime; if the KB import fails, it reports a real failure.
- Chinese/English existing flows and the original batch auto-finalize path
  retain their legacy behavior. The Vietnamese local-model repair action is
  guarded rather than silently requesting Ollama.
- **Not yet integrated:** durable ChatGPT chapter-notes/character-state
  proposal with native author approval and continuity receipts. Do not call
  the AI-derived memory complete until that is implemented.

### 2. Archive and restore
- The title bar **Backup** action now opens a main-process Save dialog and
  produces a ZIP via `archiveProject`. Authorization is bound to a live
  project session; the renderer cannot select the project root to archive.
- Main process snapshots SQLite with the active `better-sqlite3` connection,
  skips transient WAL/SHM files, rejects symbolic links and refuses
  overwriting the target. Its ZIP contains SHA-256 receipts for every file.
- A separate Python CLI supports backup, verify and **restore into a new,
  nonexistent directory**. It never overwrites a working project.
- For best non-SQLite vector index consistency, do not run AI writing,
  imports, or index rebuild during backup. Close the app for a fully
  quiescent Python CLI backup.
- Restore UI is not yet implemented, and GUI archive writer currently
  enforces ZIP32/size caps (single file <=256 MiB, total <=2 GiB).

Commands:

```powershell
python -X utf8 scripts\ssr_project_archive.py backup --project "D:\MyNovel" --output "D:\Backup\MyNovel.ssr.zip"
python -X utf8 scripts\ssr_project_archive.py verify --archive "D:\Backup\MyNovel.ssr.zip"
python -X utf8 scripts\ssr_project_archive.py restore --archive "D:\Backup\MyNovel.ssr.zip" --destination "D:\RestoredNovel"
```

### 3. Reader
- Finalized chapters show **Đọc truyện** in the existing editor.
- Reader mode is display-only and supports font size 14–30 px and comfortable
  spacing; closing the mode returns to the original locked draft view.
- Reader makes no DB calls or content edits. Existing export TXT/Markdown
  remains available.
- **Not yet implemented:** native full-screen shelf, previous/next chapter
  controls and persistent reading progress.

### 4. Batch Writer checkpointed staging
- `scripts/ssr_chatgpt_batch.py` supports:
  `start --dry-run`, `start`, `append`, `submit`, `status`.
- Preflight reads SQLite **read-only**, requires blueprints, rejects existing
  chapters, and requires the previous chapter to be finalized.
- Scene data is UTF-8 with SHA-256 receipt, indexed in sequence, and persisted
  atomically. Same idempotency key and same hash returns the prior receipt;
  mismatching retries are rejected. Candidate text is not automatically
  considered a finalized/draft chapter by SSR.
- **Not yet integrated:** a native DraftRepository-backed batch importer,
  context/canon revision invalidation, ChatGPT tool surface, GUI batch progress
  and human batch approval. Never bypass this boundary with manual SQLite
  updates or represent staged candidates as app drafts.

Example (for a *new synthetic project only*, not `test-1`):

```powershell
python -X utf8 scripts\ssr_chatgpt_batch.py --project "D:\MyNovel" start --batch pilot01 --start 2 --count 2 --dry-run
python -X utf8 scripts\ssr_chatgpt_batch.py --project "D:\MyNovel" start --batch pilot01 --start 2 --count 2
python -X utf8 scripts\ssr_chatgpt_batch.py --project "D:\MyNovel" append --batch pilot01 --chapter 2 --index 1 --text-file "D:\scene01.txt" --key chapter2-scene1-v1
python -X utf8 scripts\ssr_chatgpt_batch.py --project "D:\MyNovel" submit --batch pilot01 --chapter 2
```
